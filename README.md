# ゲノム対戦

ゲノム解析学 2025年度の過去問100問を使った学習・クイズ対戦アプリ。ゲスト参加で、ゲームロビーから4つのモードを選べます。

- 公開URL: https://9hckg4shj6-glitch.github.io/genome-battle/
- LINEに流すときは末尾に `?openExternalBrowser=1` を付ける（外部ブラウザで開く方が安定）

## 明るい／暗いデザイン

画面上部の「ライトモード／ダークモード」で、元の黒のロビーと、アイボリー・ミントの背景に白いカードを使った明るいロビーを切り替えられます。初回は暗いデザイン。選択は端末に保存され、再読み込み後も復元します。学習・対戦・復習ノートでも切り替え可能で、入力や進行は維持します。同じブラウザで開いた別タブにも反映します。

`src/theme.ts`がテーマと切り替えボタンを管理し、`index.html`で初回描画前に保存済みテーマを適用します。配色は`src/style.css`に定義しています。

## 4つのモード

- **マッチング対戦**：同じ人数・制限時間の参加者を自動で組み合わせる、2〜8人の早押し対戦。
- **一人で学習**：分野・問題数を選び、時間制限なしで解答。正解と解説を読んでから次へ進み、終了後は誤答・未解答・迷った問題を再学習できます。
- **AI対戦**：ビギナー／スタンダード／エキスパートの3段階。回答速度・正答率をサーバ側で決める自動対戦相手です（外部の生成AIや追加のAPIキーは使いません）。先に5問正解するか、最大15問で決着。
- **対戦室作成**：標準は公開ルーム。ホームの「対戦室作成」に待機中の公開ルームが表示され、名前を入力して一覧から選ぶだけで誰でも参加できます。作成時・待機中にホストが鍵をかけると一覧から消え、招待リンク（部屋番号＋招待キー）を持つ人だけが新しく参加できます。2人以上集まったらホストが開始できます。

学習・AI対戦は再読み込み後も同じ問題から復帰できます。対戦の結果画面も再読み込み後に復元します。

## 学習成績と復習

- **学習成績**：終了した一人学習・復習コースの問題数、正答率、学習回数。
- **対戦成績**：AIと対人を別々に集計し、対戦数、勝利数、敗北・引き分け、獲得得点を表示。対戦の早押し得点は学習の正答率に混ぜません。対人の同率首位は引き分けです。
- **正解したけど迷った**：正答後の解説と振り返り画面で記録・解除できます。復習ノートの「迷った問題」タブから見返し・再演習でき、既存の「間違えた問題」「保存した問題」は維持します。
- **対戦直後の復習コース**：AI対戦・対人対戦の結果画面で、その試合の誤答・未解答・迷った正答を重複なく集めます。内訳と問題数を表示し、時間制限なしの学習へ直接移動できます。振り返り画面で迷った記録を追加すると対象にも反映します。復習コースの成績は学習側に記録します。

成績は端末のプレイヤー識別子に紐づくサーバー上の完了データから集計します。過去の記録もモード別に集計し直し、再読み込みで重複加算しません。未完了の学習・対戦と、待機中に終了した部屋は集計対象外です。復習ノートの保存・迷った記録はこのブラウザの端末保存です。旧版の混合カウンターは削除せず保持しますが、新しい成績表示には使いません。

`src/learning.ts` が成績表示・復習対象を管理し、`src/learning.css` は明／暗両テーマの追加表示を定義します。

## 構成

- 静的サイト（Vite + TypeScript）を GitHub Pages で配信。`npm run deploy` でビルドして `gh-pages` ブランチへ push（.env.local の Supabase 設定が埋め込まれる）
- Supabase: プロジェクト `genome-battle`（ref `hfuixjjfhjjvvzcnlfhv`・東京・Free）。判定・進行はすべて `supabase/migrations/` の RPC（001 本体・002 人数と制限時間・003 一人学習とAI対戦・004 対戦室の開始条件・005 公開ルームと鍵付き招待・006 成績の分離）。状態が変わると Realtime Broadcast（`battle:<match_id>`）で配信
- 画面：`src/main.ts` はロビーと対人対戦、`src/solo.ts` は一人学習・AI対戦、`src/ui.ts` は共通描画と端末の記録。
- AI対戦は約1秒ごとにRPCで状態を確認します。正誤・勝敗・時間切れをサーバ時刻で判定し、相手の回答予定はクライアントへ返しません。
- 公開している `public/questions.json` には正解・解説を入れていない。正解と簡略版の解説はDBにあり、決着した問題だけ返す

## 問題の更新

正は問題演習アプリ側（さらにその正は `~/Documents/試験解説作成/output/data/*.json`）。

```bash
node scripts/import-questions.mjs   # questions.json・図・supabase/seed.generated.sql を再生成
```

`seed.generated.sql`（正解キー入りのため Git 管理外）を Supabase の SQL Editor で実行（upsert なので何度でも可）。

新しいプロジェクトでは、Realtime に一度クライアントが接続するまで `realtime.send` が作られない。SQL適用後にアプリを一度開いてから動作確認する。

## 動作確認

```bash
# .env.local に VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY
npm run dev
npm run build  # 型チェックと本番ビルド
node scripts/check-learning.mjs # 成績集計・迷った記録・復習対象の回帰確認
node scripts/check-modes.mjs # 一人学習・AI対戦・対戦室の回帰確認
node scripts/bots.mjs 16   # ボット16人で同時にランダム対戦（競合・配信・完走の確認）
node scripts/bots.mjs 9 3 6   # 3人部屋・1問6秒の設定で9体（3部屋に分かれることの確認）
```

`check-learning.mjs` は既存ノートの保持、正答のみの迷った記録、対象の重複除去、モード別集計、実際に完了した対人戦、待機中の終了の除外、再取得時の安定性を確認します。

`check-modes.mjs` と `check-learning.mjs` は `.env.local` と、fixture操作用の `~/.supabase-token` を使います。独自に作成したテスト用セッションだけを操作・削除し、正解キーや認証情報は出力しません。所有者確認、正解の非公開、二重送信、AIの先着判定、時間切れ、5問先取、ルーム定員・ホスト権限・公開一覧・招待キーの非公開・鍵の切り替え・同時入室・開始済み／期限切れ部屋の除外を検証します。

## サーバ更新と公開

新規環境では `supabase/migrations/001_battle.sql` から `006_performance.sql` まで番号順に適用し、問題のseedを取り込んでください。既存環境では未適用のマイグレーションだけを先に適用します。2026年10月1日の更新で003・004・005・006を既存Supabaseに適用しました。005適用前に作成された招待ルームは非公開のまま引き継ぎます。公開一覧は5秒ごとに更新し、満員の部屋は参加できない表示にします。鍵を一度外してから再びかけると招待キーを更新します。

`npm run deploy` はフロントの配信のみを行います。サーバ更新と動作確認を先に済ませてから実行してください。
