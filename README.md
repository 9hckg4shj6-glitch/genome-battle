# ゲノム対戦

ゲノム解析学 2025年度の過去問100問を使った学習・クイズ対戦アプリ。ゲスト参加で、ゲームロビーから4つのモードを選べます。

- 公開URL: https://9hckg4shj6-glitch.github.io/genome-battle/
- LINEに流すときは末尾に `?openExternalBrowser=1` を付ける（外部ブラウザで開く方が安定）

## ホーム画面のアイコン

ホーム画面・ブラウザーのアイコンは、珊瑚色とアイボリーの結び目のデザインを使用します。公開URLからホーム画面に追加してください。既に追加したショートカットに旧アイコンが残る場合は、そのショートカットを削除して、公開URLから追加し直してください。

画像は`public/icons/`に置き、`index.html`でブラウザー用32px・48pxとiPhone用180pxのPNGを指定しています。`public/manifest.webmanifest`で192px・512pxのPNGを指定し、GitHub Pagesのサブパスでも解決できる相対URLを使います。1024pxの元画像も同じフォルダーに保存しています。画像に角丸や透明な余白は付けていません。

## 明るい／暗いデザイン

画面上部の「ライトモード／ダークモード」で、元の黒のロビーと、アイボリー・ミントの背景に白いカードを使った明るいロビーを切り替えられます。初回は明るいデザイン。初めて開いた人には、ホームの切り替えボタンの下に「画面の明るさを変えられます」という吹き出しを出します。切り替えるか「わかった」を押すと、以後は表示しません。小さい画面でもボタンに「ライト／ダーク」の文字を残します。選択は端末に保存され、再読み込み後も復元します。学習・対戦・復習ノートでも切り替え可能で、入力や進行は維持します。同じブラウザで開いた別タブにも反映します。

`src/theme.ts`がテーマと切り替えボタンを管理し、`index.html`で初回描画前に保存済みテーマを適用します。配色は`src/style.css`に定義しています。

## 押した手応えと画面遷移

- **モードカード**：押すと沈み、離すと弾んで戻ります。指・カーソルの位置にモード色の光が灯り、上辺の線が伸び、矢印が塗りつぶされます。浮き上がりやアイコンの傾きはマウス操作の端末だけで、スマートフォンではタップ後に浮いたまま残りません。
- **画面遷移**：モードを選ぶと、押したカードのアイコンと見出しが設定画面の見出しへ移動し、「ホームへ」で元のカードへ戻ります。ヘッダーは動かさず、本文だけを切り替えます。使い方ガイド・復習ノート・過去問一覧も同じ動きで開きます。対応していないブラウザでは従来どおり即時に切り替わります。
- **入場演出**：ホームや設定画面に切り替わったときだけ、内容を上から順に表示します。入力や通信による再描画では再生しません。
- **共通のボタン**：すべてのボタン・選択肢に押下の縮みを付け、主要ボタンは光沢と影、末尾の矢印は「進む」方向へ動きます。Androidではモードに入る瞬間に短く振動します。

端末の「視差効果を減らす／動きを減らす」設定では、遷移・入場・押下の動きをすべて止めます。`src/motion.ts`が遷移と光の位置、`src/motion.css`が動きの速さ・曲線・押下・入場を管理します。

## 4つのモード

- **マッチング対戦**：同じ人数・制限時間の参加者を自動で組み合わせる、2〜8人の対戦。全員が各自の画面で選択肢を選び、全員がそろうか制限時間になると正答と解説を表示します。正解した人は全員1点。
- **一人で学習**：分野・問題数を選び、時間制限なしで解答。正解と解説を読んでから次へ進み、終了後は誤答・未解答・迷った問題を再学習できます。
- **AI対戦**：ビギナー／スタンダード／エキスパートの3段階。回答速度・正答率をサーバ側で決める自動対戦相手です（外部の生成AIや追加のAPIキーは使いません）。先に5問正解するか、最大15問で決着。
- **対戦室作成**：標準は公開ルーム。ホームの「対戦室作成」に待機中の公開ルームが表示され、名前を入力して一覧から選ぶだけで誰でも参加できます。作成時・待機中にホストが鍵をかけると一覧から消え、招待リンク（部屋番号＋招待キー）を持つ人だけが新しく参加できます。2人以上集まったらホストが開始できます。

学習・AI対戦は再読み込み後も同じ問題から復帰できます。対戦の結果画面も再読み込み後に復元します。

## 学習成績と復習

- **学習成績**：途中までの一人学習・復習コースも含む問題数、正答率、回答を見た件数、完了した学習回数。解答・回答確認の時点でサーバーに記録します。
- **対戦成績**：AIと対人を別々に集計し、対戦数、勝利数、敗北・引き分け、獲得得点を表示。対戦の得点は学習の正答率に混ぜません。対人の同率首位は引き分けです。
- **正解したけど迷った**：正答後の解説と振り返り画面で記録・解除できます。復習ノートの「迷った問題」タブから見返し・再演習でき、既存の「間違えた問題」「保存した問題」は維持します。
- **対戦直後の復習コース**：AI対戦・対人対戦の結果画面で、その試合の誤答・未解答・迷った正答を重複なく集めます。内訳と問題数を表示し、時間制限なしの学習へ直接移動できます。振り返り画面で迷った記録を追加すると対象にも反映します。復習コースの成績は学習側に記録します。

成績はこのブラウザのプレイヤー識別子に紐づくサーバーの記録から集計します。学習は未完了分も含めて問題ごとに一度だけ記録し、完了回数は最後まで終えたときだけ増えます。回答を見た問題も取り組み数・正答率の分母に含み、正解数には加えません。AI・対人対戦は完了した試合だけが対象で、待機中に終了した部屋は対象外です。復習ノートの保存・迷った記録はこのブラウザの端末保存です。旧版の混合カウンターは削除せず保持しますが、新しい成績表示には使いません。

`src/learning.ts` が成績表示・復習対象を管理し、`src/learning.css` は明／暗両テーマの追加表示を定義します。

## 学習レベル・分野マスタリー・試験準備度

`017_mastery.sql`を016の後に適用してください。一人学習・復習コースの永続記録（`study_answer_records`）だけから計算します。新しい記録の書き込みはなく、既存の記録にも初回表示から反映されます。

- **学習レベル（XP）**：正解10・不正解3・回答を見た1XP。同じ問題を同じ日（日本時間）に再び解いた分は半分（切り捨て）。問題ごとに一度だけ、最初の正解に+10（初めての解答で正解）または+15（以前の誤答・回答確認から克服）。Lv1→2は20XP、以後1レベルごとに必要XPが6ずつ増えます（Lv30で累計3016XP、全問を2〜3周が目安）。XPは減りません。
- **問題の状態**：直近2回連続で正解＝習得、直近3回以上連続で正解＝定着（誤答・回答確認で数え直し）、それ以外の取り組み済み＝取り組み中、記録なし＝未着手。「迷った」は端末保存のため、記録中の問題はクライアント側で取り組み中として数えます。
- **試験準備度**：習得以上の問題数 / 全問題数。ホームの「学習レベル」カードに内訳の帯グラフと凡例を表示します。
- **分野マスタリー**：13分野ごとに★1＝全問に取り組んだ、★2＝全問習得以上、★3＝全問定着。ホームのカード内の折り畳み一覧（再取得中も開閉状態を保持）と、問題演習コーナの分野カードに表示します。
- **結果画面**：一人学習・復習コースの終了時に、その学習で得たXPとレベルアップを表示します（`get_mastery`の`p_session`）。
- 対戦（AI・対人）はXPに含めません。対戦の記録は1日・7日で整理されるため、含めるとXPが後から減ってしまうためです。

`src/mastery.ts`と`src/mastery.css`が画面を担当します。最新値は端末にキャッシュし、取得前・通信失敗時は前回の値を表示します。

```bash
node scripts/check-mastery.mjs # レベル曲線・★・準備度・迷った除外・XP規則・同日半減・ボーナス・状態判定・今日/セッションのXP・端末分離・RLS
```

## 選択肢の並び替え・通信表示・フレンド

- **選択肢の並び替え**：学習・AI・対人・復習コースで問題ごとにシャッフルします。同じセッションの問題は再描画・再読み込みでも同じ順番。対人では全参加者が同じ順番です。表示番号と内部の解答番号を分け、サーバーには元の選択肢indexを送ります。振り返りと新しく保存するノートにも出題時の順序を保持します。以前のノートは元の順番で表示します。
- **通信状態**：画面上部に接続確認中・接続良好・リアルタイム同期中・定期通信で同期・通信エラー・オフラインを表示。最終応答時刻と応答時間は表示のツールチップで確認できます。通信失敗時は「再接続」で状態を確認し直せます。各RPCは10秒でタイムアウトし、入力エラーを通信切断として扱いません。対戦の既存の定期通信による復帰も維持します。
- **フレンド**：画面上部の「フレンド」から、10文字のコード交換で申請できます。相手が承認すると双方の一覧に追加。申請取消・拒否・解除、オンライン／オフライン、表示名の保存、コードのコピーに対応します。申請と招待は件数バッジで通知します。
- **フレンド招待**：対戦室の作成者が待機中にフレンド画面を開くと「この部屋に招待」が表示されます。承認済みの相手だけに送り、相手は届いた招待の「参加する」から公開・鍵付きの両方に入れます。招待は10分間、開始済み・終了済みの部屋には参加できません。鍵を変更した場合とフレンド解除後は以前の招待を無効にします。通信失敗時の参加再試行は重複入室しません。

フレンドは現在のブラウザのプレイヤー識別子に紐づきます。コードは相手に共有するための番号で、プレイヤー識別子や招待キーは一覧に表示しません。フレンド一覧は画面を開いている間は約10秒ごと、通常は約30秒ごとに更新。オンライン表示は直近60秒の応答が基準です。

`src/choices.ts`が順序と元の解答番号の対応、`src/connection.ts`が通信表示、`src/friends.ts`がフレンド画面を担当します。`007_friends.sql`のRLS付きテーブルとRPCに申請・承認・招待を保存します。

## 文字サイズ・図の拡大・対戦室の分野指定

- **文字サイズ**：画面上部の「標準・大・特大」で問題文・選択肢・長い解説・振り返りの文字を拡大します。「過去問・問題と解説」の一覧の問題文にも同じ設定を適用します。選択は端末に保存し、別タブと再読み込み後にも反映。学習・対戦の進行を維持したまま切り替えられます。
- **図の拡大**：問題や復習ノートの図をタップすると拡大画面を開きます。＋／−で全体表示の1〜4倍に拡大し、スマートフォンでは指で上下左右に移動できます。「全体表示」で戻し、「閉じる」またはEscapeで元の画面へ。対戦中は制限時間が進み続けることも表示します。
- **対戦室の分野指定**：「対戦室作成」の「対戦室の分野」で全分野または13分野から選びます。例：DNA複製は6問の中だけで出題。サーバーでも分野を検証し、最大15問を重複なく選びます。5問先取、問題が先に終わった場合は最高得点で決着。同点は引き分けです。分野と最大問題数は公開一覧・待機画面・フレンド招待にも表示し、公開／鍵付きどちらでも使えます。既存の部屋とマッチング対戦は全分野のままです。

`src/readability.ts`と`src/readability.css`が文字サイズと拡大画面を管理します。`008_room_fields.sql`は問題の分野情報・対戦室の指定分野・短い試合の完了記録を追加します。

## 準備完了・再戦・学習の後回しと出題方法

- **準備完了**：待機画面で各自が「準備完了」を押し、取り消しもできます。人数がそろっても未準備の参加者がいれば開始しません。対戦室は全員の準備後に作成者が開始し、マッチングは全員の準備後に指定人数または既定の待機時間で自動開始します。新規参加・準備取消で自動開始の待機時間を取り消します。サーバーでも参加資格・準備状態・直近の通信を確認します。
- **同じメンバーで再戦**：終了画面・振り返りのボタンから、前のメンバー・分野・定員・制限時間を引き継ぐ新しい試合へ参加できます。全員が参加し、準備完了になると3秒のカウントダウンで開始。得点と準備はリセットし、問題を選び直します。再戦は元の参加者だけが入れる専用ルームで、公開一覧やフレンド招待には出しません。同時に押しても再戦先は一つだけ。元の試合の成績と復習履歴は保持します。待機中の一時切断は準備だけを取り消し、戻る資格を保持します。
- **後回し**：複数問の一人学習・復習コースでは強調した「後で解く」ボタンで未解答の問題を末尾へ送れます。残りを解いた後に戻り、問題ごとの選択肢は元の並びを保ちます。再読み込みにも対応。解答・正解・誤答として数えず、最後の1問は解答して完了します。AI対戦の時間制限や得点には影響しません。
- **問題演習コーナ**：「一人で学習」の入口カードを押すと、見出しが移る演出とともに専用ページへ移動。学習する分野を複数選べ（選択はこの端末に保存）、選んだ分野の問題を混ぜて出題します。出題配分は2分野以上を選んだときに選べます。画面は`src/practice.ts`と`src/practice.css`です。
- **二つの学習開始ボタン**：「未着手の問題を優先的に演習」「ランダム演習」を設置。分野と問題数の指定は両方で有効です。未着手はこの端末のプレイヤーが一人学習・復習でまだ解答も回答の確認もしていない問題。未着手内はランダム、不足する場合は演習済みからランダムに補います。後回しは未着手のまま。誤答・中断した学習での解答も着手に含みます。ランダム演習は着手に関係なく、指定した分野から重複なく出題します。

`009_ready_rematch.sql`と`010_study_queue.sql`を適用してください。未着手の初期値はサーバーに残る既存の学習履歴・進行中の解答から引き継ぎ、以後はセッションとは別のRLS付き記録で保持します。正解や未出題の問題順は解答前に公開しません。画面の追加スタイルは`src/sessions.css`です。

## みんなの正答率・AI対戦への切り替え

`018_question_stats.sql`を017の後に適用してください。

- **みんなの正答率**：一人学習・復習・AI対戦（お手つきを含む）・対人対戦の解答から、**端末ごとに初めて解いたときの正誤だけ**を数えます。同じ人が繰り返し解いても率は上がりません。「回答を見る」は不正解として数えます（学習成績と同じ扱い）。5人未満の問題は「集計中」と表示します。
  - 表示：一人学習・AI対戦の解説、振り返り・復習ノートのカード、過去問一覧（見出しに難しさ、開くとメーター）、対人戦の解説（3秒なので1行）。
  - 難しさ：80%以上＝基本、60%以上＝標準、40%以上＝やや難、それ未満＝難問。自分の結果と組み合わせて「多くの人が正解している基本問題です」「難問に正解しました」などの一言を添えます。
  - 集計は`question_first_answers`（RLS有効・ポリシーなし）に保存し、`get_question_stats()`は問題ごとの人数と正解数だけを返します。対戦・セッションが整理されても残ります。記録はトリガーで付け足すだけで、失敗しても解答・進行は止めません。既存の学習記録・残っている対戦・AI対戦の履歴から初回分を移します。
  - 端末は1分に1回まで取得し、前回の値を端末に保存します。一度も取得できていない（018未適用など）ときは何も表示しません。
- **AI対戦への切り替え**：マッチング対戦で一人のまま15秒待つと、待機画面に「いまは対戦相手が見つかりません」とAI対戦の提案を出します。難易度を選んで「AIと対戦する」を押すと、相手探しをやめてすぐにAI対戦が始まります。提案中も相手探しは続け、相手が来たら提案を消し、音と振動で知らせます。「このまま待つ」で45秒は出しません。待ち時間は画面に表示し、同じ試合なら再読み込み後も引き継ぎます。切り替えたAI対戦の結果画面には「マッチング対戦を探す」を出します。AIの難易度はこの端末に保存します。

画面は`src/stats.ts`・`src/stats.css`（正答率）と`src/main.ts`・`src/sessions.css`（待機画面）です。

```bash
node scripts/check-question-stats.mjs          # 表示ロジック＋初回だけの集計・回答を見た・AIのお手つき・対人戦・RLS
node scripts/check-question-stats.mjs --local  # 表示ロジックだけ（DBに触れない）
```

検証スクリプトとボットは、終了時に自分の端末の初回解答を`question_first_answers`から削除します（テストの解答を正答率に残さないため）。

## 構成

- 静的サイト（Vite + TypeScript）を GitHub Pages で配信。`npm run deploy` でビルドして `gh-pages` ブランチへ push（.env.local の Supabase 設定が埋め込まれる）
- Supabase: プロジェクト `genome-battle`（ref `hfuixjjfhjjvvzcnlfhv`・東京・Free）。判定・進行はすべて `supabase/migrations/` の RPC（001 本体・002 人数と制限時間・003 一人学習とAI対戦・004 対戦室の開始条件・005 公開ルームと鍵付き招待・006 成績の分離・007 フレンドと通信確認・008 対戦室の分野指定・009 準備と再戦・010 学習キューと未着手記録・014 全員解答・016 マッチングの人数3択と1問20秒・解説3秒・017 学習レベルと習得状態・018 みんなの正答率）。状態が変わると Realtime Broadcast（`battle:<match_id>`）で配信
- 画面：`src/main.ts` はロビーと対人対戦、`src/solo.ts` は一人学習・AI対戦、`src/ui.ts` は共通描画と端末の記録。
- AI対戦は約1秒ごとにRPCで状態を確認します。正誤・勝敗・時間切れをサーバ時刻で判定し、相手の回答予定はクライアントへ返しません。
- 公開している `public/questions.json` には正解・解説を入れていない。正解と簡略版の解説はDBにあり、決着した問題だけ返す

### わからない問題の回答を見る

`011_view_study_answer.sql`を適用してください。一人で学習・復習の出題中に「わからないので回答を見る」を押すと、選択肢を選ばず正答と解説を表示します。正解数には加えず、学習済みとして未着手優先から外し、復習ノートに「回答を見た」と記録します。次の問題・結果・振り返り・再読み込みに対応します。後回しと異なり、その問題の解答段階を終えます。AI対戦では利用できません。サーバーが所有者・モード・問題・バージョンを確認し、二重押しや後回し・解答との競合を防ぎます。

## 中断して保存・続きから再開・途中学習の記録

`012_saved_study_records.sql`を011の後に適用してください。

- 一人学習・復習コースの出題中または解説画面で「中断して保存」を押すと、ホームへ戻ります。「中断してホームへ」とロゴから戻る場合も保存します。保存確認に失敗した場合は現在の画面に残り、再試行できます。
- ホーム上部の「保存した学習の続き」に分野・取り組み済み件数・残り問題数を表示。「続きから再開」で同じ問題、選択肢の順番、得点、後回し、回答を見た状態、解説を復元します。複数の学習を残せます（4件目以降は折り畳み）。タブを閉じても同じブラウザの識別子から一覧を取得できます。未完了の学習は7日で削除しません。
- 最後の問題の回答確認後、結果に進む前も解説から再開できます。コースを完了すると保存一覧から外れます。AI対戦はこれまで通りの時間制限付き進行を維持し、中断保存の対象にしません。
- `study_answer_records`は正解・誤答・回答確認を、採点と同じトランザクションで記録します。セッションID＋問題IDで重複を防ぎ、後回し・未解答は加算しません。同じ問題を別のコースで再演習した場合は、新しい取り組みとして数えます。
- `study_completions`に完了回数を保存。古い完了セッションが整理されても学習成績は残ります。既存の残存履歴と、次へ進む前の解答・回答確認も移行します。
- 新しい記録テーブルはRLS付きで、公開クライアントからの直接参照・更新を許可しません。再開用一覧に正答・解説・未出題の問題順を含めません。別端末・別ブラウザへの同期はこの更新の対象外です。

動作確認：

```bash
node scripts/check-study-resume-client.mjs # 保存失敗、二重押し、空のタブから復元、遅延応答、ノートの重複防止
node scripts/check-study-resume.mjs # 所有者、複数保存、後回し・解説復元、途中集計、二重送信、保持期限、RLS
```

回帰スクリプトは独自のUUIDを使用し、永続した問題記録・完了記録も含めて自分のfixtureだけを清掃します。

## 出題配分の選択

`013_study_distribution.sql`を012の後に適用してください。

- 一人学習で「すべての分野」を選ぶと、「過去問の配分で出題」「分野を均等に出題」を選べます。選択は同じブラウザで保持します。
- 過去問配分は従来の全問題から選ぶ方式です。ランダム演習では各問題を同じ確率で選ぶため、問題数の多い分野ほど出やすく、毎回の分野内訳は変わります。未着手優先は全候補の未着手から優先して選びます。
- 分野均等では、各分野の問題数をできるだけ同じにします。13分野で26問なら各分野2問。端数はランダムに割り当て、問題が足りない分野の分は他の分野から補います。どちらも指定した問題数を重複なく出題します。
- 均等配分と未着手優先を組み合わせた場合は、各分野の枠内で未着手から選び、不足分をその分野の演習済みから補います。出題順は分野を混ぜてランダムにします。
- 特定分野を選ぶと配分の選択を無効にし、その分野だけから出題します。復習コースは復習対象を使います。AI・対人対戦の出題設定には適用しません。
- 中断して保存・再読込・続きから再開でも、その演習の配分と問題順を保持します。保存一覧と学習中に配分を表示します。既存の保存済み学習はそのまま再開できます。

`check-study-distribution.mjs`は1〜100問の配分、不足の補充、重複除去、候補分野の制約、分野内の未着手優先、旧クライアントと復習・AIの互換性、保存した設定・問題順、正解の非公開、不正設定の拒否を確認します。クライアントのラジオボタン・説明・設定送信・再開時の表示は`check-study-resume-client.mjs`で確認します。

## 保存した学習一覧の折り畳み

ホーム上部の「保存した学習の続き」は最初に閉じて表示します。見出し全体をクリック・タップすると、保存した学習と「続きから再開」ボタンが開きます。件数は閉じていても確認でき、もう一度押すと閉じられます。キーボードのEnter・Spaceでも操作できます。同じ画面内の再描画や一覧の再取得で開閉状態を保ち、ページを開き直した場合は閉じた状態から始めます。「学習を保存しました」の通知は閉じた状態でも表示します。

## 過去問・問題と解説

`015_question_catalog.sql`を014の後に適用してください。

- 一人で学習の設定画面の下にある「過去問・問題と解説」から、収録している全100問の問題文・図・選択肢を閲覧できます。分野で絞り込めます。
- 問題を押すと開き、正解の選択肢と解説を表示します。正答・解説は開いた問題だけを`get_question_answer`で取得し、同じ画面内では再取得しません。取得に失敗した場合は再取得ボタンを表示します。
- 選択肢は元の順番（1〜5）で表示します。閲覧は学習記録・未着手の判定・復習ノートに影響しません。

`check-question-catalog.mjs`は、`.env.local`のanon keyによる公開クライアントで全100問の`get_question_answer`を確認します。応答のID、正答番号が選択肢の範囲内の整数であること、解説が空でないこと、存在しないIDが`null`を返すことを検証します。出力は確認件数と合否のみで、正答・解説・認証情報を表示しません。参照だけを行い、学習データは作成・変更しません。

```bash
node scripts/check-question-catalog.mjs
```

## 問題演習コーナ

「一人で学習」の演習設定は「問題演習コーナ」にまとめ、最初は閉じたカードで表示します。押すとプレイヤー名、分野、問題数、出題配分と演習開始ボタンが開き、もう一度押すと閉じます。設定変更や学習進捗の再取得で開閉状態を保ちます。「過去問・問題と解説」は独立したカードから開けます。
